# Аудит кода Token Clicker

## Архитектура и поток данных

Ядро — чистые переходы `(GameState) => GameState` в `src/economy/`: `engine.ts` (цены, Доход, Клик, оффлайн, Престиж), рядом `catalog.ts`, `upgrades.ts`, `perks.ts`, `events.ts`, `glitches.ts`, `crystal.ts`, `achievements.ts`/`shadow.ts`, `format.ts`. Правило «не изменилось — верни тот же объект» соблюдается и используется стором для пропуска сайд-эффектов.

Единственный мутабельный владелец — `src/store/useGameStore.ts` (827 строк): тик, звуки, тосты, флоатеры, UI-слой (`activeTab`, `buyAmount`, `eventCaught`, `burst`, пауза ленты). Цикл — `setInterval 50 мс` в `src/App.tsx` → `tick(dt)` → `advanceTime` (активный `advance` или `applyOffline` при `dt ≥ OFFLINE_THRESHOLD_SEC`) → `advanceEvents`/`advanceGlitches`/`collectCrystals` → `awardAchievements` → `localStorage.setItem` на каждом тике. Компоненты (`ClickColumn`, `OfficeColumn`, `ShopColumn`, `Modals`, `GoldenToken`, `NewsTicker`) только читают стор и зовут экшены, экономику не пересчитывают сами — за вычетом оговорок ниже.

## Технический долг и смешение слоёв

Экономика в целом изолирована хорошо, но протечки есть: `ShopColumn.tsx` (~1000+ строк) считает `bulkCost/maxAffordable/incomeGain/shortfall`, делит перки на обычные/особые (`isGenPerkId`, `genPerkCost`) и знает про цены Откупа и кристаллов — новая валюта или скидка потребует править и движок, и магазин. `Modals.tsx` (оффлайн-отчёт, статистика темпа Compute) и `GoldenToken.tsx` (`grantAmount/crashAmount`, `activeSpec`) тоже содержат куски денежных формул и разборов таблиц. Стор раздут: игровые правила (взвод «Краха», зеркало `eventCaught`, слухи, `raiseUprising`, тосты Восстания) лежат рядом с UI-состоянием, модульные счётчики (`floaterCounter`, `toastCounter`, `lastTemplateIndex`, `rumorIn/rumorSeq` в ленте) — глобальный мутабельный стейт вне `GameState`. Рендер идёт целиком 20 раз в секунду (подписки `s.state`), тонкие оптимизации точечные (счётчик Токенов через `rAF` + прямую запись в DOM, пыль Сцены предвычислена). Сериализация всего `GameState` в `localStorage` на каждом тике — лишний I/O без дросселирования.

## Что мешает расширять

Новая система = правки в 4–5 местах: поле `GameState` (`state.ts`) + `MIGRATIONS` (`save.ts`) + переход (`engine.ts` или новый модуль) + экшен в сторе + 2–3 компонента + тесты. `Upgrade`/`PerkEffect` — дискриминированные объединения, хорошей формы, но каждый новый эффект — это новая ветка в `modelBaseIncome/clickValue/globalMult` без реестра эффектов; порядок множителей неявный и задокументирован только комментариями. Слот события один (`state.event`), параллельные баффы невозможны без переделки `events.ts`/`glitches.ts`. Два источника времени (`lastTick` как игровые часы vs `Date.now()` в Престиже/статистике) — ловушка для новых таймеров. Стили — инлайн-`style` + CSS-переменные без системы, `ShopColumn`/`OfficeColumn` перегружены анимационной логикой (сквош, искры, прыжки маскотов).

## Тесты

`npm test`: 4 файла, 218 тестов, ~0.6 с — всё зелёное (в `AGENTS.md` ещё указано 174, цифра устарела). Покрыты инварианты каталога (монотонность цены/Дохода по Рангу, ×1000 на Поколение, ±30% `softMod`), оффлайн-кап, «интервал не платится дважды», миграции, экшены стора. Пробел: `vite.config.ts` включает только `src/**/*.test.ts`, компонентные `.test.tsx` молча не запустятся — UI проверяется только руками.

## Самые хрупкие места

Сохранения: единственный экземпляр прогресса — `localStorage['ai-tycoon-save']`; `migrate` молча отбрасывает неизвестные id Моделей/Апгрейдов/Перков, `importSave` отклоняет весь файл при дробном индексе Поколения; bump `SAVE_VERSION` без записи в `MIGRATIONS` перезаписывает старые сейвы. Баланс: Ранг сортируется по `iq` из снимка AA — обновление снапшота может пересортировать Ранги и цены; `softMod` держит ±30%, но зависит от медианы цен. Точность: `computeShortfall` уходит в 0 около 1e50, `formatNumber` — суффиксная лестница до 1e300; `catchUpPaid/eventCaughtAt/nextEventAt/nextGlitchAt` переживают перезагрузку только потому, что лежат в `GameState` — новый флаг вне его сломается на первом релоаде.

## Топ-5 препятствий

1. **Стор-бог** — `src/store/useGameStore.ts`: игровые правила, звуки, тосты и UI-слой в одном файле; новая механика = ещё один экшен + зеркальные флаги.
2. **Магазин-бог** — `src/components/ShopColumn.tsx`: цены, скидки, особые перки, Откуп, кристаллы в render; новую валюту/скидку придётся дублировать здесь.
3. **Плоский `GameState` + ручные миграции** — `src/economy/state.ts`, `src/economy/save.ts`: каждое поле = bump + `MIGRATIONS` + риск потери сейва; сдерживает новые системы.
4. **Стопка множителей без реестра** — `src/economy/engine.ts` (`modelBaseIncome`, `clickValue`, `globalMult`): новый эффект = новая ветка с неявным порядком; легко инвертировать баланс.
5. **Одиночный слот событий и часы `lastTick`** — `src/economy/events.ts`, `src/economy/glitches.ts`, `src/App.tsx`: параллельные эффекты и новые таймеры упираются в один `state.event` и путаницу `lastTick`/`Date.now()`.
